# 텔레그램 공시 채널

공개 채널: [Finalyze.AI | AI 재무분석](https://t.me/finalyze_ai)

홈페이지와 같은 코스피200·코스닥150 구성 기업만 게시합니다. `indexUniverse.js`가 읽는 KRX 구성종목 스냅샷을 공유합니다([출처·기준일·갱신 절차](index-universe.md)). 새로 편입된 기업은 최초 성공 조회 시 과거 공시 기준만 설정하고 이후 새 공시부터 게시합니다. 사업·반기·1분기·3분기 보고서와 재무 금액을 확인한 잠정실적을 대상으로 하며, 월간 판매대수·자회사 공시·철회된 공시는 제외합니다. 홈페이지의 최신 5개 목록을 재사용하지 않고 DART 목록의 모든 페이지에서 새 접수번호를 수집합니다.

기존 `disclosure-alerts` 작업에서 관심 기업 푸시와 함께 수집하므로 별도 DART 폴링이나 LLM 호출은 없습니다. Vercel Schedules의 15분 간격과 최대 15분 지터 때문에 게시가 지연될 수 있습니다. 잠정실적은 기존 원문 파서로 금액·단위·기간을 읽고 증감률을 계산합니다. 원문 수치를 읽지 못한 경우와 정기보고서는 제목·공시일·원문·서비스 링크를 게시합니다. 서비스 링크는 공시 선택 화면으로 이동하며 AI 분석을 자동 요청하지 않습니다.

수치가 있는 알림은 각 지표 아래 **전년동기 대비**를 첫 줄에 굵게 표시하고, **전기(직전 기간) 대비**는 다음 줄의 참고 정보로 구분합니다. 원문에서 확인한 비교 기간도 함께 표시하며 전기를 무조건 직전분기로 간주하지 않습니다. 전년동기 수치가 없으면 확인 불가를 명시하고, 비교 기준이 0이면 증감률을 만들지 않습니다. 새 형식은 이후 발송 메시지에 적용하며 과거 게시물을 재발송하지 않습니다.

## 연결

1. BotFather에서 전용 봇을 만들고 채널 관리자에 추가합니다. 메시지 게시 권한만 부여합니다.
2. 운영 환경에 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`(검증한 숫자 채널 ID), `TELEGRAM_ENABLED=true`를 등록하고 배포합니다. Preview에는 운영 키를 연결하지 않습니다. `DATABASE_URL`과 `CRON_SECRET`은 기존 알림 작업과 같습니다.
3. `npm run check:telegram-disclosures`로 검증하고 인증된 `POST /api/jobs/disclosures` 또는 Vercel 일정의 수동 실행으로 첫 수집을 확인합니다. 최초 성공 조회는 기업별 기준만 만들고 과거 공시는 일괄 발송하지 않습니다. 신규 편입 기업도 동일합니다.

토큰은 저장소·출력·DB에 남기지 않습니다. 유료 대량 방송은 비활성화되어 있습니다. 비활성화하려면 `TELEGRAM_ENABLED=false`로 배포합니다. 개인정보나 사용자 관심 기업 목록을 채널로 전송하지 않습니다.

## 전송 기록

`accountStore.js`가 Neon/SQLite에 채널·기업별 최초 수집 기준과 `(chat_id, receipt)` 고유 전송 기록을 만듭니다. 성공한 메시지 ID를 보관하며 기록은 30일 후 정리합니다. 목록 조회는 최대 7일 범위와 하루 겹침을 사용하므로 정리된 오래된 공시가 다시 게시되지 않습니다.

- `baseline`: 최초 연결에서 확인한 과거 공시
- `pending`: 발송 대기 또는 명확한 429 거절 후 재시도 대기(최대 5회)
- `sent`: Telegram이 수락했고 DB에 메시지 ID 기록 완료
- `uncertain`: 타임아웃·5xx·발송 중 프로세스 종료 등 수락 여부 불명. **자동 재발송하지 않습니다.** 채널에서 접수번호를 확인한 뒤 운영자가 처리합니다. Telegram Bot API에는 전송 멱등성 키가 없어 완전한 정확히 한 번 전송을 보장할 수 없습니다.
- `failed` / `skipped`: 명확한 실패 또는 대상 기업 목록에서 제외

401/403은 채널을 하루 중지하며 429는 Telegram의 `retry_after` 동안 채널 전체를 멈춥니다. 정상 전송은 1.2초 간격, 작업당 최대 8건으로 처리하고 남은 대기열은 다음 일정에서 이어갑니다.

## 관리자 개인 신규 회원 알림

`signupNotifications.js`는 같은 봇으로 관리자의 **개인 대화**에 가입 시각(KST), 발송 시점의 오늘 신규 회원 수·현재 전체 회원 수를 보냅니다. 이름·이메일·회원 식별자는 메시지에 포함하지 않습니다. 먼저 관리자가 봇의 시작 버튼을 눌러야 합니다.

- Production에 `TELEGRAM_ADMIN_CHAT_ID`(확인된 개인 대화의 양수 숫자 ID), `TELEGRAM_SIGNUP_ENABLED=true`를 설정합니다. 기존 `TELEGRAM_BOT_TOKEN`을 재사용하고 공개 채널 ID는 변경하지 않습니다. Preview에는 연결하지 않습니다.
- 최초 실행에서 기준 시각만 설정하므로 기존 회원은 소급 발송하지 않습니다. 이후 생성된 회원만 최근 7일 범위에서 수집하며 재로그인은 알리지 않습니다. 7일을 넘긴 장기 중단 동안의 가입은 소급하지 않습니다.
- 기존 15분 주기 공시 작업에서 실행합니다. 최대 15분 지터와 대기열에 따라 지연될 수 있으며 가입 직후 즉시 발송을 보장하지 않습니다. 로그인 요청에서 Telegram API를 호출하지 않습니다.
- `app_signup_recipients`와 `app_signup_deliveries`에 기준 시각·중복 방지·발송 상태를 기록합니다. 계정 삭제 시 해당 기록도 삭제하고 발송 기록은 30일 후 정리합니다. 대상·전송 상태·일시 중지 모두 공개 채널과 분리합니다.
- 한 실행에서 최대 8건을 1.2초 간격으로 보냅니다. 429만 최대 5회 재시도하며 401/403은 개인 수신자를 하루 중지합니다. 수락 여부 불명·전송 중 프로세스 종료는 `uncertain`으로 남겨 자동 중복 발송을 피합니다.
- `npm run check:signup-notifications`로 검증합니다. 중지하려면 `TELEGRAM_SIGNUP_ENABLED=false`로 배포합니다.
