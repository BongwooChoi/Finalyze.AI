# 텔레그램 공시 채널

공개 채널: [Finalyze.AI | AI 재무분석](https://t.me/finalyze_ai)

홈페이지와 같은 `recentDisclosures.js`의 대표기업 60개만 게시합니다. 사업·반기·1분기·3분기 보고서와 재무 금액을 확인한 잠정실적을 대상으로 하며, 월간 판매대수·자회사 공시·철회된 공시는 제외합니다. 홈페이지의 최신 5개 목록을 재사용하지 않고 DART 목록의 모든 페이지에서 새 접수번호를 수집합니다.

기존 `disclosure-alerts` 작업에서 관심 기업 푸시와 함께 수집하므로 별도 DART 폴링이나 LLM 호출은 없습니다. Vercel Schedules의 15분 간격과 최대 15분 지터 때문에 게시가 지연될 수 있습니다. 잠정실적은 기존 원문 파서로 금액·단위·기간을 읽고 증감률을 계산합니다. 원문 수치를 읽지 못한 경우와 정기보고서는 제목·공시일·원문·서비스 링크를 게시합니다. 서비스 링크는 공시 선택 화면으로 이동하며 AI 분석을 자동 요청하지 않습니다.

## 연결

1. BotFather에서 전용 봇을 만들고 채널 관리자에 추가합니다. 메시지 게시 권한만 부여합니다.
2. 운영 환경에 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`(검증한 숫자 채널 ID), `TELEGRAM_ENABLED=true`를 등록하고 배포합니다. Preview에는 운영 키를 연결하지 않습니다. `DATABASE_URL`과 `CRON_SECRET`은 기존 알림 작업과 같습니다.
3. `npm run check:telegram-disclosures`로 검증하고 인증된 `POST /api/jobs/disclosures` 또는 Vercel 일정의 수동 실행으로 첫 수집을 확인합니다. 최초 성공 조회는 기업별 기준만 만들고 과거 공시는 일괄 발송하지 않습니다. 신규 편입 기업도 동일합니다.

토큰은 저장소·출력·DB에 남기지 않습니다. 유료 대량 방송은 비활성화되어 있습니다. 비활성화하려면 `TELEGRAM_ENABLED=false`로 배포합니다. 개인정보나 사용자 관심 기업 목록을 채널로 전송하지 않습니다.

## 전송 기록

`accountStore.js`가 Neon/SQLite에 채널·기업별 최초 수집 기준과 `(chat_id, receipt)` 고유 전송 기록을 만듭니다. 성공한 메시지 ID를 보관하며 기록은 30일 후 정리합니다. 목록 조회는 최대 7일 범위와 하루 겹침을 사용하므로 정리된 오래된 공시가 다시 게시되지 않습니다.

- `baseline`: 최초 연결에서 확인한 과거 공시
- `pending`: 발송 대기 또는 명확한 429 거절 후 재시도 대기(최대 5회)
- `sent`: Telegram이 수락했고 DB에 메시지 ID 기록 완료
- `uncertain`: 타임아웃·5xx·발송 중 프로세스 종료 등 수락 여부 불명. **자동 재발송하지 않습니다.** 채널에서 접수번호를 확인한 뒤 운영자가 처리합니다. Telegram Bot API에는 전송 멱등성 키가 없어 완전한 정확히 한 번 전송을 보장할 수 없습니다.
- `failed` / `skipped`: 명확한 실패 또는 대상 기업 목록에서 제외

401/403은 채널을 하루 중지하며 429는 Telegram의 `retry_after` 동안 채널 전체를 멈춥니다. 정상 전송은 1.2초 간격, 작업당 최대 8건으로 처리하고 남은 대기열은 다음 일정에서 이어갑니다.
