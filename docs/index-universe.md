# 공시 대상: 코스피200·코스닥150

메인 최신 실적 공시와 공개 텔레그램 채널은 한국거래소의 코스피200·코스닥150 구성 기업을 대상으로 합니다. 자체 인지도 판단·시가총액 상위 N개·ETF 보유종목으로 대체하지 않습니다. 기업 검색·차트·AI 분석과 회원 관심 기업의 메일·푸시 범위에는 이 제한을 적용하지 않습니다.

## 적용 중인 목록과 출처

- `public/data/disclosure-universe.json`: 공식 구성종목의 종목코드·종목명·조회 기준일·출처. 소개 페이지에서 공개합니다.
- `indexUniverse.js`: 두 목록의 공식 확인 개수, 코드 형식, 중복, 날짜, 출처를 검증하며 복사본을 반환합니다.
- 원문: [KRX 지수정보](https://index.krx.co.kr/) → KRX 지수 → 주가지수 → KOSPI/KOSDAQ 시리즈 → 해당 지수 → 구성종목. 이 공개 경로에서는 로그인 없이 CSV를 내려받을 수 있습니다. 각 지수의 상세 원문 URL도 스냅샷에 저장합니다.

스냅샷은 기준일 당시의 구성입니다. 서버 요청마다 KRX를 조회하거나 정기 변경을 자동 반영하는 방식은 아닙니다. 지수 정기·수시 변경 적용 시 공식 목록을 다시 확인하고 아래 절차로 갱신·배포합니다. 조회일과 적용일을 혼동하거나 미래 적용 예정 목록을 미리 활성화하지 않습니다.

## 갱신

현재 적용한 2026-11-06 공식 CSV는 코스피200 **201종목**, 코스닥150 **150종목**, 합계 **351종목**입니다. 코스피200 개요 화면의 구성종목수 201과 CSV 건수를 대조했습니다. 지수명 숫자에 맞추기 위해 임의로 한 종목을 제외하지 않습니다.

1. KRX에서 두 지수를 각각 선택하고 **동일한 거래일**로 조회한 뒤 CSV를 내려받습니다. 파일명만으로 지수를 추정하지 말고 선택한 지수명·기준일·전체 건수를 확인합니다.
2. 다음 명령으로 검증한 두 파일을 함께 가져옵니다. UTF-8/EUC-KR, 인용부호 안의 쉼표, 선행 0을 보존합니다.

```powershell
npm run update:index-universe -- --as-of YYYY-MM-DD --kospi200 C:/path/kospi200.csv --kosdaq150 C:/path/kosdaq150.csv
npm run check:index-universe
npm run check:recent-disclosures
npm run check:telegram-disclosures
npm run check:public-pages
```

공식 개수가 지수명의 숫자와 다르면 `--kospi200-count 201 --kospi200-count-note "KRX 기준일·개요 건수와 CSV 대조 확인"`처럼 확인 개수와 근거를 명시해야 가져올 수 있습니다. 기본값은 200/150이며 불완전한 파일의 길이를 자동으로 정상 건수로 인정하지 않습니다.

3. Git diff로 편입·편출·기준일을 검토합니다. `check:index-universe`는 모든 종목이 `dart.db`의 기업 코드와 1:1로 매핑되는지도 검사합니다. `npm run sync:index-companies`로 누락 종목의 공식 DART 매핑을 조회하고, 결과를 확인한 후 `npm run sync:index-companies -- --apply`로 해당 기업만 갱신합니다(기존 dart.db는 .data에 백업). 이후 재검사합니다. 영문자를 포함하는 6자리 종목코드도 보존합니다. 회사명 유사도나 ETF 이름으로 매핑하지 않습니다.
4. 정상 목록·문구를 함께 배포합니다. 비정상 개수·중복·불완전한 CSV는 저장 전에 실패하며 이전 파일을 유지합니다. 공식 지수 자체가 예외적으로 200/150개와 다르면 공식 개요·CSV 건수를 대조한 뒤 명시적 개수 옵션과 근거를 기록합니다. 부족한 수를 임의 기업으로 채우지 않습니다.

## 운영 동작

- 메인 화면은 기업별 최신 1건, 전체 최대 5건을 유지합니다. API `universe`에 구성종목 기준일·출처·개수·revision을 반환합니다.
- 구성종목 스냅샷 해시를 공시 목록의 Redis 네임스페이스에 포함해 이전 대상의 캐시와 섞지 않습니다.
- 기존 DART 목록 수집·공유 캐시·호출 제한을 그대로 사용합니다. 기업별 별도 폴링이나 LLM 호출은 추가하지 않습니다.
- 텔레그램 신규 편입 기업은 최초 성공 조회에서 과거 공시를 기준으로만 기록합니다. 이후 새 공시부터 게시하고, 편출 기업은 기존 대기열에서도 발송을 건너뜁니다. 기존 기업의 발송 이력·중복 방지는 초기화하지 않습니다.
- 대상 확대에 따라 실적 시즌 알림량과 원문 확인량이 증가할 수 있습니다. 기존 전송 간격·작업 마감·대기열을 유지하며 장애 시 DART 직접 호출로 우회하지 않습니다.

보관용 과거 GIF·화면 캡처는 촬영 당시 기록입니다. 현재 기준은 코드·소개 페이지·수정한 발표 HTML에 반영합니다.
