# OPEN DART API 프로젝트

OPEN DART API를 사용하여 금융감독원 공시 데이터를 가져오는 프로젝트입니다.

## 설치 방법

```
npm install
```

## 환경 변수 설정

1. 프로젝트 루트 디렉토리에 `.env` 파일을 생성합니다.
2. 아래와 같이 OPEN DART API 키를 설정합니다:

```
OPEN_DART_API_KEY=여기에_실제_API_키를_입력하세요
```

## OPEN DART API 키 발급 방법

1. [OPEN DART](https://opendart.fss.or.kr/) 웹사이트에 접속합니다.
2. 회원가입 후 로그인합니다.
3. [API 키 신청](https://opendart.fss.or.kr/intro/main.do) 메뉴에서 API 키를 신청합니다.
4. 발급받은 API 키를 `.env` 파일에 설정합니다.

## 회사코드 파일 다운로드

DART API를 사용하기 위해서는 회사의 고유번호(corp_code)가 필요합니다. 다음 명령어로 회사코드 파일을 다운로드할 수 있습니다:

```
npm run download-corp-code
```

다운로드한 ZIP 파일을 파싱하여 JSON 파일로 변환하려면 다음 명령어를 실행합니다:

```
npm run parse-corp-code-simple
```

이 명령어는 다음 두 개의 파일을 생성합니다:
- `corpCode.json`: 모든 회사 정보 (약 11만개)
- `listedCorpCode.json`: 상장 회사 정보만 포함 (약 3,800개)

## 회사 검색하기

회사 이름으로 검색하려면:

```
npm run search-corp-name "회사이름"
```

또는 직접 스크립트 실행:

```
node searchCorpCode.js -n "회사이름"
```

종목 코드로 검색하려면:

```
npm run search-stock-code "종목코드"
```

또는 직접 스크립트 실행:

```
node searchCorpCode.js -c "종목코드"
```

예시: 삼성전자 검색
```
node searchCorpCode.js -c "005930"
```

## 실행 방법

```
npm start
```

## 메인 화면 최신 실적 공시

- 검색창 아래에 코스피200·코스닥150 구성 기업의 정기보고서·잠정실적을 기업별 최신 1건씩, 최대 5개·1열로 표시합니다. 대상은 한국거래소 지수 구성종목이며 `public/data/disclosure-universe.json`에 출처·기준일과 함께 저장합니다. 홈페이지와 공개 텔레그램이 `indexUniverse.js`의 동일한 목록을 사용합니다. 선정 기준과 적용 중인 목록은 소개 페이지에서 공개하며, 갱신 절차는 [지수 구성종목 관리](docs/index-universe.md)를 참고하세요.
- 메인 화면의 텔레그램 안내는 PC에서 오른쪽에, 좁은 화면에서는 최신 공시 목록 아래에 표시합니다. `https://t.me/finalyze_ai` 공개 채널로 연결하며 기업 선택 후 분석 화면에서는 숨깁니다.
- 목록의 ‘공시 보기’는 기업 정보·공시 목록으로 이동하고 해당 공시를 강조합니다. 새 탭·새로고침·공유 주소에서도 분석을 자동 실행하지 않으며, 사용자가 ‘분석하기’를 눌러야 재무·AI 분석을 요청합니다.
- `/api/recent-disclosures`는 OPEN DART의 정기공시 A와 공정공시 I002를 조회합니다. 기본 최근 30일, 결과가 5개 미만이면 최근 90일로 넓힙니다. 최신 5개보다 오래된 페이지는 조회를 중단하되 같은 날짜의 연결·정정 공시는 계속 확인합니다. 정정 전·철회·자회사 공시를 제외하고 같은 날 연결 잠정실적을 우선합니다.
- 잠정실적 원문의 재무금액을 확인해 판매대수만 발표한 공시는 제외합니다. 목록을 만드는 과정에서는 OpenAI를 호출하지 않습니다.
- 일시적인 통신 오류·HTTP 408/5xx는 한 번 재시도합니다. 원문 일부를 끝내 확인하지 못해도 다른 공시는 표시하고 부분 조회 안내를 제공합니다. 실패한 원문을 부적격으로 캐시하지 않으며, 부분 조회 결과는 1분 후 다시 수집할 수 있습니다. API 사용량 제한 등 DART 업무 오류와 HTTP 403/429는 즉시 재시도하지 않습니다.
- Redis·메모리·CDN에서 목록을 5분 캐시하고 브라우저도 메인 화면이 보일 때 5분마다 확인합니다. 수집 잠금은 Redis에서 공유하여 여러 서버·재배포 후에도 한 번만 수집합니다. 조회 실패 후에는 서버 전체가 1분 동안 재수집을 쉬며, 24시간 이내의 마지막 목록이 있으면 확인 시각과 함께 표시합니다. 수동 새로고침 버튼은 없으며 조회 실패·갱신 지연 시에만 ‘다시 시도’를 표시합니다.
- `dartClient.js`는 모든 웹 API의 DART 호출을 한곳에서 처리합니다. 인증키별로 Redis의 원자 연산을 사용해 요청 시작 간격을 1초 이상, 하루 전송 예약량을 8,000회 이하로 제한합니다(KST 날짜). 캐시 적중은 DART 호출로 세지 않습니다. 같은 키를 쓰는 외부 프로젝트·로컬 스크립트의 호출은 이 제한에 포함되지 않습니다.
- 목록·재무 API 응답은 5분, 접수번호별 ZIP 원문은 7일 동안 공유합니다. HTTP 403/429 또는 DART 011/012를 받으면 5분, DART 020을 받으면 다음 KST 날짜까지 추가 호출을 중지합니다. 공유 캐시 장애 시 운영 서버가 제한 장치를 우회해 DART를 직접 호출하지 않습니다.
- Vercel에는 무료 `finalyze-dart-cache`(Upstash Redis, 자동 유료 전환 비활성)를 연결했습니다. `KV_REST_API_URL`/`KV_REST_API_TOKEN` 또는 `UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN`을 사용합니다. 로컬은 해당 변수가 없으면 메모리 저장소를 사용하며 여러 프로세스를 통합하지 않습니다.
- `npm run check:recent-disclosures`는 실제 외부 API 호출 없이 선정·페이지 처리·KST 날짜·동시 요청·장애 복구를 검사합니다. `npm run check:public-pages`는 HTTP 응답과 공개 페이지를 검사합니다.
- `npm run check:dart-client`는 공유 응답·동시 요청·호출 속도·하루 한도·차단 응답·인증정보 비노출을 검사합니다.

## Google 로그인 · 관심 기업 · 공시 알림

- 비회원은 기업 검색·공시 조회·정기보고서의 차트·표·비율·연간 추이와 잠정실적 비교 차트를 이용합니다. AI 재무분석과 잠정실적의 AI 설명은 로그인한 회원에게 제공합니다. `GET /api/provisional-financials?rcept_no=`가 DART 원문 표에서 수치·단위·기간을 직접 읽으며 차트 생성에는 LLM을 호출하지 않습니다. 자동 추출할 수 없는 표는 원문 확인을 안내하며 숫자를 추측하지 않습니다. `npm run check:provisional-financials`로 병합 셀·당기/누계 구분·단위·음수·빈 값을 검사합니다.
- 두 AI API는 `accounts.requireAnalysis`에서 유효한 로그인 세션과 세션별 CSRF 토큰을 확인한 뒤 실행합니다. GET 방식의 잠정실적 API도 CSRF 토큰이 필수입니다. 로그인 유도 미리보기는 장식용이며 실제 AI 분석을 생성하지 않습니다. 로그인만으로 자동 분석하지 않고, 보고 있던 공시의 ‘AI 분석 시작하기’를 눌러 이어갑니다. 이미 로그인한 회원이 공시의 ‘분석하기’를 누르면 기존처럼 시각화와 AI 분석을 함께 요청합니다.

- Google Identity Services의 ID 토큰을 서버에서 서명·대상·유효기간·브라우저 nonce까지 확인합니다. Google `sub`는 서비스 전용 HMAC ID로 바꾸며 이름·사진·원본 토큰은 저장하지 않습니다. 로그인 쿠키는 HttpOnly/Secure/SameSite=Lax, 최대 7일이며 DB에는 세션 토큰 해시만 저장합니다. 변경 API는 출처와 CSRF 토큰을 검사합니다.
- 기업 검색 결과에서 ☆ 버튼으로 최대 50개 관심 기업을 등록합니다. 상단 ‘관심 기업’에서 다른 기기와 같은 목록을 보며, 기업을 눌러도 AI 분석은 자동 요청하지 않습니다.
- 계정 데이터는 `DATABASE_URL`(또는 `ACCOUNTS_DATABASE_URL`)의 Neon Postgres에 저장합니다. DART 공유 캐시는 회원 DB로 사용하지 않습니다. 운영 DB는 무료 `finalyze-users`이며 로컬에서 DB URL이 없으면 Git에서 제외된 `.data/accounts.sqlite`를 사용합니다. `npm run setup:accounts`로 스키마를 준비하고 `npm run check:accounts`로 외부 API 없이 계정·알림 동작을 검사합니다.
- `.env.example`의 Google client ID, `APP_ORIGIN`, `SESSION_SECRET`, `USER_ID_SECRET`, `USER_DATA_KEY`, VAPID 키와 `CRON_SECRET`이 필요합니다. Google 웹 클라이언트의 JavaScript 원본에 서비스 주소와 로컬 주소를 등록합니다. client secret은 사용하지 않습니다. 세션·식별자·암호화 키는 서로 다른 난수를 사용하며 `USER_DATA_KEY`는 32바이트 base64입니다. **식별자·암호화·VAPID 키를 재배포마다 재생성하지 않습니다.**
- 푸시는 사용자가 허용한 기기별로 등록하며 최대 5개 기기를 지원합니다. 구독 주소와 암호 키는 AES-256-GCM으로 암호화해 저장합니다. iPhone은 홈 화면에 추가한 웹앱에서 알림을 허용해야 합니다. 로그아웃하면 현재 기기 구독을 해제하고, 계정 삭제는 모든 세션·관심 기업·구독·발송 기록을 삭제합니다. `/privacy`에서 처리 정보를 안내합니다.
- `vercel.json`의 Vercel Schedules 작업이 약 15분 간격(플랫폼 지연 가능)으로 `POST /api/jobs/disclosures`를 호출합니다. 이 경로는 `Authorization: Bearer CRON_SECRET`을 요구합니다. Schedules는 Beta이며 Hobby의 최소 간격·지터 15분 조건을 사용합니다. Preview에는 운영 계정 키를 연결하지 않습니다.
- 알림 수집은 모든 구독자의 관심 기업을 합쳐 DART A/I002 목록을 조회하며, 기존 공유 캐시와 호출 한도를 사용합니다. 관심 기업마다 최초 성공 조회는 기존 공시 기준을 설정하고 이후 새로 확인한 정기보고서·잠정실적부터 알립니다. 공시 확인·알림에는 LLM을 호출하지 않습니다.
- DB 잠금과 발송 대기열로 중복 작업을 막고 사용자·접수번호·채널·기기별 중복 발송을 방지합니다. 전송 실패는 최대 5회 재시도하고, 매번 관심 기업·수신 동의를 다시 확인합니다. 만료된 구독은 삭제합니다. 전송 직후 프로세스가 종료된 예외 상황에서는 같은 푸시가 재전달될 수 있습니다. 공급자에 이미 전달된 알림은 해제 후에도 도착할 수 있습니다.
- 이메일은 발신 설정이 준비되기 전까지 비활성입니다. 무료 Gmail을 사용할 때는 전용 계정의 2단계 인증을 켜고 앱 비밀번호를 발급한 뒤 운영 환경에 `MAIL_PROVIDER=gmail`, `GMAIL_USER`, `GMAIL_APP_PASSWORD`를 설정합니다. 앱 비밀번호는 Vercel의 비밀 환경변수에만 보관하고 개인 계정 로그인 비밀번호를 사용하지 않습니다. TLS SMTP로 전송하며 발신 주소는 인증한 Gmail 계정으로 고정합니다.
- 나중에 발신 도메인을 검증하면 `MAIL_PROVIDER=resend`, `RESEND_API_KEY`, `MAIL_FROM`으로 전환할 수 있습니다. 두 제공업체 모두 설정되어도 한 곳으로만 전송하며 실패 시 다른 제공업체로 자동 전환하지 않습니다. Gmail은 Google의 발송 한도와 보안 정책이 적용되는 소량 운영용입니다. SMTP는 발송 후 응답이 끊긴 경우 재시도 시 같은 메일이 재전달될 수 있습니다.
- 메일 알림은 사용자가 별도로 동의해야 켜집니다. 동의 전에는 이메일을 저장하지 않으며 수신 주소는 암호화하고 해제 시 삭제합니다. `npm run check:accounts`는 발신 설정·TLS·수신 동의·해제·공시 링크·전송 오류의 정보 비노출을 외부 발송 없이 검사합니다.
- 이메일 알림의 ‘알림 켜기’는 해당 항목 바로 아래에 Google 계정 확인 버튼을 펼칩니다. 모달 상단으로 이동하지 않으며, 취소하거나 창을 닫으면 뒤늦게 도착한 인증 응답을 무시합니다.
- 푸시·메일의 ‘알림 켜기/끄기’ 옆에 현재 켜짐/꺼짐을 표시합니다. 처리 중에는 회전 표시와 ‘켜는 중/끄는 중’을 보여주고, 완료·실패는 해당 항목 바로 아래에서 안내합니다. 메일은 Google 계정 확인과 서버 저장이 끝나야 켜짐으로 표시됩니다.

## 로그인·AI 사용량 보호

- 공유 링크의 `corp`는 8자리 숫자이며 `/api/companies/corp/:corpCode`가 회사 DB에서 확인한 정보만 복원합니다. URL의 `name`은 표시 정보로 신뢰하지 않습니다. 기업·공시 문자열은 HTML 이스케이프하고 순수 텍스트 제목은 `textContent`로 표시합니다.
- 두 AI API는 같은 회원 ID의 Redis 사용량을 공유합니다. 기본값은 회원당 KST 하루 10회(`AI_MEMBER_DAILY_LIMIT`), 전체 하루 200회(`AI_GLOBAL_DAILY_LIMIT`), 회원당 동시 1건·전체 동시 4건·회원 요청 간격 10초입니다. 일일 환경변수를 `0`으로 설정하면 AI를 중단합니다. 허용된 호출은 실패해도 횟수에 포함하고, 차트·로그인 미리보기·공시 알림은 횟수를 사용하지 않습니다. 이 한도는 분석 시도 수이며 금액 단위의 공급자 지출 한도를 대신하지 않습니다.
- OpenAI 전체 실행은 재시도를 포함해 120초로 제한하며, 잠금은 실제 작업 종료 후 해제합니다. 서버가 종료되면 180초 lease가 만료됩니다. 공유 저장소 장애 시 유료 호출을 허용하지 않습니다.
- 로그인 challenge는 Redis에서 10분 동안 단회 소비하며 발급·완료 단계별 IP 제한을 사용합니다. 활성 세션은 계정당 최대 5개입니다. DB의 계정 행을 먼저 잠그는 별도 statement와 `ReadCommitted` 트랜잭션으로 세션·관심 기업·푸시 한도를 유지합니다. 같은 푸시 endpoint의 계정 이전도 직렬화합니다.
- `npm run check:accounts`는 외부 발송 없이 보안 회귀와 기존 계정 UI를 검사합니다. `npm run check:security-integration`은 `TEST_POSTGRES_URL`(loopback의 전용 `finalyze_security` DB), `TEST_PG_MODULE`(테스트용 `pg` 모듈 경로), `TEST_REDIS_CONTAINER`(임시 Redis 컨테이너명)가 설정된 경우 실제 PostgreSQL·Redis의 동시성을 검사합니다. 환경변수가 없으면 해당 통합 검사는 명시적으로 건너뜁니다. 운영 DB를 지정하지 않습니다.

## 관리자 페이지

- AI 한도 도달은 파란 이용 안내, 동시 요청/간격 제한은 노란 대기 안내, 실제 장애는 빨간 오류로 구분합니다. 정기·잠정 AI API가 동일한 사유 코드를 사용하며 일일 한도에는 KST 자정 초기화를 안내합니다. AI를 중지하거나 한도를 0으로 설정하면 별도 제공 중지 안내를 표시합니다. 한도/대기 안내 시 차트를 유지하고 자동 재요청하지 않습니다.

- `/admin`에서 회원 수·KST 당일 가입·로그인 유지 회원/세션·메일/푸시 등록·오늘 AI 허용 횟수·대기 알림·마지막 수집을 집계합니다. 로그인 유지 수는 실시간 접속자 수가 아닙니다. 회원 이름·이메일·기기 주소는 관리자 API에 반환하지 않습니다.
- Vercel Production의 `ADMIN_EMAILS`에 관리자로 허용할 Google 이메일을 쉼표로 구분해 등록하고 재배포합니다. 지정 계정으로 Google 로그인을 한 번 다시 하면 서버가 검증된 이메일을 확인해 권한을 부여합니다. 이메일은 별도 서비스 HMAC으로 저장하고 매 관리자 요청에서 현재 allowlist와 대조합니다. `ADMIN_EMAILS`가 비어 있으면 관리자 권한이 없습니다. 첫 회원·클라이언트 플래그·요청 본문으로 권한을 부여하지 않습니다.
- 관리자 API는 회원 세션·CSRF와 서버의 관리자 권한을 모두 확인하며 설정 변경은 정확한 Origin을 요구합니다. `/admin`, 관리자 API는 no-store/noindex로 제공하고 서비스 워커 캐시에서 제외합니다.
- AI 제공 중지·회원/전체 일일 횟수·동시 실행 수·요청 간격·계정의 세션/즐겨찾기/푸시 한도를 저장할 수 있습니다. DB의 설정이 환경변수 기본값보다 우선하고 재배포 후에도 유지되며 다음 요청에 적용됩니다. 세션은 다음 로그인에서 새 개수 한도를 적용하고, 기존 즐겨찾기·푸시를 자동 삭제하지 않습니다. 설정 저장으로 일일 사용량을 초기화하지 않습니다.
- 설정 버전으로 동시 저장을 검사하고 충돌은 409로 거절합니다. 변경 전후 값과 관리자 가명 ID를 같은 트랜잭션에 기록하고 최근 100건을 보관합니다. 화면에는 최근 10건을 표시합니다. API 키·원본 이메일·민감한 환경변수를 수정하는 인터페이스는 제공하지 않습니다.
- `npm run check:admin`은 허용 계정/일반 회원/비회원·검증되지 않은 이메일·CSRF·출처·값 검증·동시 저장·감사 기록 실패 시 rollback·동적 한도 적용을 외부 호출 없이 검사합니다.

## 공개 페이지와 검색엔진 확인

- `/`는 기업 검색·분석 화면, `/about`은 소개·사용법·분석 기준·FAQ입니다.
- `sitePages.js`가 공통 HTML에서 각 경로의 본문 표시 상태와 고유 메타데이터를 렌더링합니다. 공통 메타데이터는 `public/js/site-pages.js`에서 관리합니다.
- 기존 `/#about` 주소는 브라우저에서 `/about`으로 연결됩니다. 앱 안에서 이동할 때는 선택한 기업·공시를 유지합니다.
- 좌측 상단 브랜드 로고는 `/`로 새로 이동해 선택한 기업·공시와 분석 화면을 초기화합니다. 상단 재무분석·시스템 소개 메뉴 간 이동은 선택 상태를 유지합니다.
- 공개 URL 목록은 `public/sitemap.xml`에서 관리합니다. `lastmod`와 소개 문서 확인일은 실제 공개 내용이 변경된 날짜를 사용합니다.
- `npm run check:public-pages`로 HTTP 응답, 초기 HTML의 본문·메타데이터, 리디렉션과 사이트맵을 검사합니다. 외부 DART·OpenAI 호출은 하지 않습니다.
- Search Console 소유권 확인용 `public/google6cac55f830514a99.html`은 배포 후에도 유지해야 합니다. 실제 색인 여부·사이트맵 제출 상태는 Search Console과 Bing Webmaster Tools에서 별도로 확인합니다.
